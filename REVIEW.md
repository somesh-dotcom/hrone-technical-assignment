# REVIEW.md

List of defects identified and resolved in starter `app/main.py`:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | 1) Evaluates `minutes > 10` on whole floor minutes instead of checking if strictly > 10:00 (600 seconds) after `shift_start`. 2) Replaces hour/minute on `punch_in`'s date, calculating relative to the wrong calendar day on overnight shifts. 3) Lacks IST timezone awareness. | Punch-in at 09:40:01 on a 09:30 shift gives `minutes = int(601/60) = 10`, failing `minutes > 10` and returning 0 instead of 10. | Converted `punch_in` to IST, combined shift start with attendance date, checked `diff_sec > 600`, and returned `int(math.floor(diff_sec / 60))`. |
| 2 | `compute_work_hours` (lines 40–41) | Uses Python's built-in `round(..., 2)` which performs banker's rounding (round to nearest even) instead of standard half-up rounding (Rule R4). | An exact half-way duration like 4.125 hours rounds to 4.12 instead of 4.13 with banker's rounding. | Used Python `decimal.Decimal` with `ROUND_HALF_UP` (`Decimal(str(diff_sec / 3600)).quantize(Decimal('0.01'), rounding=ROUND_HALF_UP)`). |
| 3 | `compute_overtime` (lines 44–47) | 1) Uses `datetime.fromisoformat(date_str).replace(...)` which sets `shift_end` on the shift start date even for overnight shifts (`shift_end <= shift_start`). 2) Does not enforce the 30-minute minimum threshold per Rule R3 (`max(0, int(...))` counts 5 min overtime as 5). | Punch-out 25 min after shift end returns 25 instead of 0; punch-out on overnight shift 22:00–06:00 at 06:40 IST calculates overtime relative to previous day's 06:00. | Added 1 day to shift date if `shift_end <= shift_start`; checked `diff_sec >= 1800` (30 min) before calculating `math.floor(diff_sec / 60)`, returning 0 otherwise. |
| 4 | `GET /health` (lines 72–74) | Unconditionally returns `{"status": "ok"}` with HTTP 200 without verifying MongoDB connectivity. | Stopping MongoDB or misconfiguring `MONGO_URI` still returns 200 OK from `/health` instead of 503 Service Unavailable. | Added `client.admin.command('ping')` inside a try-except block, raising `HTTPException(503)` if ping fails. |
| 5 | `POST /employees` (lines 77–86) | 1) Uses check-then-insert (`find_one` then `insert_one`), susceptible to race conditions. 2) Does not validate `shift_start != shift_end`. 3) Lacks regex and length validations. 4) Sets naive local `datetime.now()` for `created_at` and does not return epoch ms. | Concurrent requests create duplicate employees; identical `shift_start` and `shift_end` are accepted; `created_at` returns datetime object instead of epoch integer. | Created unique index on `emp_code`; handled `DuplicateKeyError` -> 409; added Pydantic validation for shifts and patterns; stored UTC BSON date and serialized as epoch ms. |
| 6 | `GET /employees` (lines 88–96) | 1) Pagination skip bug: `skip = page * page_size` skips the entire first page (`skip = 1 * 20 = 20`). 2) `total` counts the whole collection ignoring the `department` filter. 3) Missing sorting by `emp_code` ascending. | `page=1` returns items 21–40 instead of 1–20; `total` is incorrect when department filter is applied. | Set `skip = (page - 1) * page_size`; passed filter query `q` to `count_documents(q)`; added `.sort("emp_code", 1)`; formatted `created_at` as epoch ms. |
| 7 | `POST /attendance/punch-in` (lines 99–122) | 1) Throws unhandled `KeyError` on `emp["shift_start"]` when employee is missing, returning 500 instead of 404. 2) Check-then-insert allows race conditions. 3) Naive timestamp handling without IST overnight shift logic (R1). 4) Truncation to seconds missing. 5) Returns `id: str(res.inserted_id)` violating API schema. | Punch-in for non-existent employee returns 500; concurrent punch-ins both succeed with 201; punch-in at 05:45 on overnight shift is assigned to current day instead of previous day. | Added 404 check for missing employee; created unique compound index `(emp_code, date)` and handled `DuplicateKeyError` -> 409; added `compute_attendance_date`; truncated to whole seconds; formatted output to match `AttendanceRecord`. |
| 8 | `GET /attendance` (lines 124–151) | 1) Loads entire matching dataset into Python memory (`list(db.attendance_logs.find(q))`) and sorts in Python, causing OOM / timeout at scale (100k docs). 2) Missing 422 validation for `date_from > date_to`. 3) Missing secondary sort on `emp_code` asc. 4) Returns invalid `id` field and unformatted BSON dates. | Request with `date_from=2026-07-10&date_to=2026-07-05` returns 200 instead of 422; high memory usage on large collections; date fields in JSON are not epoch ms. | Used DB-level pagination and sorting (`.sort([("date", -1), ("emp_code", 1)]).skip(skip).limit(page_size)`); added 422 check for date ranges; formatted all records with `format_attendance_doc`. |
| 9 | Database Indexes (startup) | Starter creates no indexes on startup, relying solely on default `_id` index. | Explain queries result in `COLLSCAN` across collections; uniqueness cannot be guaranteed under concurrency. | Added FastAPI `lifespan` hook to idempotently create unique indexes on `employees.emp_code`, `attendance_logs.(emp_code, date)`, and compound indexes for queries and aggregations. |

### Examined and confirmed NOT a defect:
1. **Default shift times (`shift_start="09:30"`, `shift_end="18:30"`)**: In line with the schema definitions in `openapi.yaml` where standard office hours default to 09:30 and 18:30 IST.
2. **Default status `PRESENT` on punch-in**: Per `openapi.yaml`, `status` defaults to `PRESENT` if not explicitly supplied in `PunchInRequest`.
3. **Absence of `id` on attendance records**: Per `DATA_MODEL.md` and `openapi.yaml`, attendance records are naturally keyed by `(emp_code, date)` and do not expose MongoDB's `_id` or an `id` field.
